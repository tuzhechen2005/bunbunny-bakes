# 🐰的大面包 在线预订系统 PRD

> **版本 2.0**（2026-10-21，设计拷问后定稿）
> 取代 V1.0《每日面团产能与订单限额系统》、V1.1《生产资源与订单限制系统》、V1.2《在线预订、订单管理与通知系统》。三份旧文档之间有冲突的地方，一律以本文和 `DECISIONS.md` 为准。
> 英文名 **Bunbunny Bakes**，域名 **bunbunnybakes.shop**（待注册）。

## 1. 一句话

熟客在网站上选好面包、日期和自提或配送，留下微信号就能预订；店主在后台确认、管理订单，系统自动保证每天不超过实际做得出的量。

## 2. 用户

| 用户 | 说明 |
|---|---|
| **顾客** | 店主微信群"🐰的大面包"里的熟客，基本都在微信里点开网站。不注册、不登录，只留微信号 |
| **店主（管理员）** | 唯一的管理员。自己做面包、自己配送。用户名加密码登录后台 |

## 3. 核心原则

1. **不超卖。** 所有名额检查在服务器端、在数据库事务里完成，两个人同时下单也不会超过上限。
2. **顾客只看到能选的。** 顾客看不到面团克数、库存等内部数据，只看到哪天能选、哪天已满、哪天已截止。
3. **店主说了算。** 上限是用来挡住网站上的超额订单的，不是用来挡店主的。店主在后台可以超限，但要写原因，并记入日志。
4. **不悄悄发生任何事。** 订单不会自动失效，不会自动改日期，也不会自动拆单。
5. **不收钱。** 网站不在线付款；顾客拿到货之后再转账。

## 4. 店主的一轮预订

1. 在后台日历上勾选这一轮做哪几天。
2. 在微信群里发通知。
3. 在后台点"开启接单"。
4. 顾客下单 → 店主收到邮件 → 加顾客微信核对 → 在后台把状态改为"已联系"→"已确认"。
5. 每晚 20:05 左右收到生产汇总邮件：明天要做多少面包、今晚和明晚各要做多少布蕾、还有哪些订单没确认。
6. 当天：制作中 → 待取货 / 待配送 → 已完成；收到转账后打开"已付款"开关。
7. 这一轮结束，点"暂停接单"。

## 5. 顾客下单流程

1. 打开网站，浏览商品（名称、照片、简介、单价、四件套餐价）。
2. 加入购物车，系统自动计算套餐价。
3. 选取货日期：只显示店主开放的日期，每个日期标注"可选 / 已满 / 已截止"，并写明截止时间（例如"周五取货，周四 20:00 截止"）。
4. 选**自提**或**配送**。选配送时显示运费，以及"再买 $X 免运费"。
5. 填**微信号**（唯一必填的个人信息）和备注（选填）。
6. 确认页：商品明细、套餐优惠、运费、总金额、日期、自提或配送、微信号。提示"无需在线付款，收到货后再付款"。
7. 点"确认提交预订"，服务器重新检查所有规则。
8. 成功页即订单专属页：订单号、明细、金额、状态"已收到，等待确认"、店主微信号、"复制订单链接"按钮（提示保存链接以便查看状态）。
9. 顾客随时打开专属链接查看状态；截止前可以自己取消。

**自提和配送的具体时间、地点，都在微信私聊里约**，网站只写"自提时间在下午 5 点以后，具体时间微信确认"。

## 6. 名额与规则（详见 `CAPACITY_RULES.md`）

| 规则 | 第一版 |
|---|---|
| 名额按哪天算 | 一律按**取货日期**。面包取货当天现做；布蕾在取货前一天晚上做，所以"取货日的布蕾名额"就等于"前一晚要做的量" |
| 面团 | 每天默认 1600 g，可按日期调整。按个算的商品：个数 × 每个克数；按大圆包算的商品（奶酪角）：⌈当天总个数 ÷ 每个大圆包切的份数⌉ × 每个大圆包克数 |
| 布蕾 | 不占面团。每天默认 24 杯，可按日期调整 |
| 配送 | 每天最多 8 单，可按日期调整，也可以设定某天不配送 |
| 截止时间 | 面包：取货日前 1 天 20:00。布蕾：取货日前 2 天 20:00。混合订单按更早的那个截止。时区一律 America/Chicago |
| 每单上限 | 每款最多 8 个（布蕾 8 杯），可改 |
| 价格 | 同一款每满 4 个用一次套餐价，不同款不混合凑套餐 |
| 运费 | 商品金额（套餐折扣后）不满 $25 收 $5，满 $25 免运费 |

## 7. 订单状态

| 后台状态 | 含义 | 占名额 | 顾客看到 |
|---|---|---|---|
| 新订单 | 刚提交，还没联系 | 是 | 已收到，等待确认（请加店主微信 xxx） |
| 已联系 | 已加微信，在等顾客回复 | 是 | 同上 |
| 已确认 | 核对过 | 是 | 已确认 |
| 制作中 | 当天开始做（可跳过） | 是 | 正在为你制作大面包！（只有布蕾时：正在为你制作布蕾！） |
| 待取货 / 待配送 | 做好了 | 是 | 可以取货了 / 正在配送 |
| 已完成 | 顾客拿到了 | 是（历史） | 已完成 |
| 已取消 | 顾客或店主取消 | 否 | 订单已取消 |
| 已拒绝 | 店主不接，例如微信联系不上 | 否 | 订单已取消 |

**付款单独记录**："已付款"开关、付款方式、付款时间，与状态无关，顾客看不到。

## 8. 第一版范围

### 做
- 顾客：菜单、购物车、选日期、自提或配送、微信号、提交、专属订单页、截止前自己取消。
- 店主后台：登录；接单开关；开放日期日历（每天的面团、布蕾、配送上限和是否配送）；订单列表、筛选、详情；改状态；付款记录；修改订单（重新检查名额）；代客下单；商品管理；设置；操作日志；未来的产能日历。
- 名额：面团、布蕾（及以后任何"独立限额"商品）、配送单数、截止时间、每单上限。
- 通知：新订单邮件、顾客取消邮件、每晚生产汇总邮件。
- 防护：防重复提交、频率限制、表单陷阱、每单上限。

### 不做（以后再说）
原材料库存、配方清单、鸡蛋换算、采购提醒；烤箱、烤盘、冷藏空间；自提时间段；Telegram / WhatsApp / 短信；发给顾客的邮件；定时开单；成本和毛利；在线付款；顾客账号；英文版。

## 9. 验收标准

1. 一天的面团用量在 1600 g 以内时可以下单；超过时，顾客无法选这一天，并会被推荐下一个能完整容纳购物车的日期。
2. 奶酪角按当天全部订单的总数计算大圆包，不按单向上取整。
3. 布蕾不占面团；布蕾超过当天上限时无法下单。
4. 截止时间之后，顾客不能再下这一天的单；含布蕾的订单提前一天截止。
5. 多人同时提交，不会超过任何上限（有并发测试证明）。
6. 取消或拒绝后，名额立即释放；待确认的订单不会自动失效。
7. 配送单数单独计算；满了只能选自提；运费规则正确。
8. 店主可以按日期调整上限；超限操作需要原因，并记入日志。
9. 顾客只能通过随机专属链接查看自己的订单，看不到任何内部数据。
10. 新订单提交后 1 分钟内，店主收到邮件；邮件发送失败不影响订单，并且会自动重试。
11. 每晚 20:05 左右收到生产汇总，汇总数字和后台一致。
12. 后台所有人工修改都有日志：谁、什么时候、改了什么、原值、新值、原因。
