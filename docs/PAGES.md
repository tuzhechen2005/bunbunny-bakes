# 页面与文案

> **手机优先。** 顾客几乎都在微信内置浏览器里打开，店主也主要在手机上用后台。每个页面先按 375 px 宽度设计，再适配电脑。
> 全中文。所有文案集中在 `src/copy.ts`，下面引号里的文字就是默认文案。
> 视觉：温暖、简洁，兔子元素点到为止。商品没有照片时显示统一的兔子占位图。

## 顾客页面

### `/` 首页（菜单 + 购物车）

- 顶部：店名"🐰的大面包"，一行接单状态：
  - 开启：「预订开放中」
  - 关闭：「暂未开放预订 🍞」+「下一轮预订开放时间请关注群内通知～」
- 商品卡片：照片、名称、简介、价格（"$2.49 / 个　4 个 $8.99"）、数量加减按钮。
  - 暂停：卡片变灰，标「暂停供应」，不能加。
  - 达到每单上限：加号变灰，提示「大量订购请加微信联系」。
- 底部固定条：已选件数、小计、「去结算」。接单关闭时可以加购物车，但按钮显示「暂未开放预订」且不能点。
- 购物车存在浏览器本地存储里；读写都包在 try/catch 里，失败了就只在内存里保存。

### `/checkout` 结算

按顺序，一屏一屏往下：

1. **购物车明细**：每行显示套餐计算，例如"奶酪角 ×5　$10.99 + $2.99 = $13.98"。
2. **选择取货日期**：日期卡片，每张显示"10/30 周五"和状态：
   - 可选：显示截止时间「10/29 周四 20:00 截止」
   - 已截止：灰色，「已截止」
   - 已满：灰色，「已满」
   - 配送已满（只在选了配送时）：「配送已满，可选自提」
   - 有商品不能在这天取（C1，N 批）：灰色，写「泡芙仅周三」（第一个受限商品的名字和可取的日子）
   - 已满 / 受限的日期如果带 `hints`，可以点开，日期下方（错误区）显示一键行：REDUCE「去掉 1 个奶酥红豆包，就能订 11/5 周四」[改好]（改购物车并选中该日期）；SPLIT「11/5 周四 可以先订 2 个，剩下 1 个可以订 11/4 周三」[先订周四] 或「泡芙只能周三取，可以分两单下」[先订其他面包（周四）]。SPLIT 的按钮只为 `here` 下单（正常确认流程），成功后购物车变成 `rest`、`bb_cart_date_v1` 记下 `restDate`，订单页写「还有 1 个泡芙在纸袋里，等你下第二单」和回结算页的按钮。没有 hints 时仍是「改成 xx」。
   - 结算页打开时如果 `bb_cart_date_v1` 里的日期可选就预选，然后清掉
   - 商品格和详情：有 `pickupWeekdays` 的商品显示小标签「仅周三、周六」
   - 购物车里有布蕾时，日期上方提示「含布蕾的订单需提前两天预订」
   - 没有任何可选日期：「暂时没有可以预订的日期，请关注群内通知～」
3. **自提或配送**：两个选项。
   - 自提：「{pickupNote}」
   - 配送：「运费 $5，满 $25 免运费」；不满时显示「再买 $X 就免运费啦」。地点和时间：「具体配送时间和地点会在微信上和你确认」
4. **微信号**：输入框，标签「你的微信号」，说明「店主会加你微信确认订单」。必填，去掉首尾空格，最多 40 个字符。
5. **备注**（选填）：最多 300 字。
6. **金额**：小计、运费、总额。
7. 提示：「无需在线付款，收到货后再付款。」
8. 按钮：「确认提交预订」。点击后立即变为「提交中…」并锁住，防止重复提交。

提交失败时的提示：

| 错误 | 提示 |
|---|---|
| FULL | 「这一天的预订名额已经满啦，可以选择下一个有空位的日期～」+ 推荐日期按钮「改成 10/31 周六」；没有推荐时「暂时没有可以容纳这个订单的日期，可以减少数量或加微信联系店主」 |
| DELIVERY_FULL | 「这一天的配送名额满了，可以改成自提～」 |
| CUTOFF_PASSED | 「这一天已经截止啦，请选择其他日期」 |
| ORDERING_DISABLED | 「暂未开放预订 🍞」 |
| RATE_LIMITED | 「提交太频繁了，请稍后再试，或加微信联系店主」 |
| 其他 | 「提交失败，请稍后再试」 |

- 刚提交时，顶部多一块：「预订提交成功！🎉」+「复制下面的链接保存好，随时打开它查看订单状态」。
- 状态（大字）：见 `DATA_MODEL.md` 第 2 节的顾客版文案。
- 「请加店主微信：{ownerWechatId}」+ 复制按钮（新订单、已联系时突出显示，之后变成小字）。
- 订单号、取货日期、自提或配送、明细、小计、运费、总额。
- 「无需在线付款，收到货后再付款。」
- 可以取消时：「取消订单」按钮（次要样式）+「{截止时间} 前可以自己取消」。点击后确认框：「确定要取消这个订单吗？」→「已取消」。

### 保存链接弹窗（`/o/{token}?new=1`，D83）

- 盖章动画结束约 0.8 秒后弹出（减少动态效果时直接弹出）；`role="dialog"`、`aria-modal`，焦点在大按钮上，焦点不离开弹窗。
- 标题「保存订单链接」；小字「点开查看订单进度！妥善保存，丢失请联系店主」；大按钮「复制订单链接」→ 成功后「已复制 ✓」（复制失败时显示链接文本方便长按复制）；底部「我已保存」。点空白处、按 Esc 都不关，只能点「我已保存」。
- 每个订单只在刚下单那次弹出。

### `/game` 消除大面包（D100–D113）

- 先到菜单（D110）：没有存档 →「开始游戏」「排行榜」；有未过期存档 → 大按钮「继续上一局」（小字「上局 N 分」）、「重新开始」（二次确认弹窗「上一局的进度会丢掉，确定吗？」）、「排行榜」。奖品一行（D108）和规则在菜单下方。「开始游戏」才进入微信号 / 昵称表单。
- 自动保存（D111）：每次投放后把 `{ v: 1, runId, seed, tiers, drops, nickname, expiresAt, score }` 写入 localStorage `bb_game_save_v1`；继续 = 用 `drops` 重放引擎重建棋盘（确定性），再接着玩，新投放追加。游戏结束、「不保存」、「重新开始」和 `expiresAt` 过期时删除存档。游戏中右上角「退出」→ 弹窗「保存进度再走 / 不保存」→ 回菜单。
- 结束弹窗（D112）：右上角 ×、下滑、Esc 都能关；关掉后看最后的棋盘，底部一条「再来一局 · 看分数」（看分数重新打开弹窗）。
- 皇冠（D113）：排行榜顶部「👑 历史最高」（`allTime`，为 null 时不显示）；结束弹窗有「我的历史最高 N」（`personalBest`），`newRecord` 时多一行「👑 新纪录！」（弹出一次，减少动态效果时不动）。
- 大面包 + 大面包（D109）：这次合并（`bigBig`）有最大的庆祝效果：闪光 + 屏幕中间放大的「+500」，随后彩色碎屑爆开（最多 200 个粒子，结束后停止 rAF）、专门的合成音效（仅在声音开启时）、Android 震动节奏；减少动态效果时只有「+500」淡入淡出。
- 接口见 API_SPEC 的游戏部分（C2：`start.expiresAt`、`leaderboard.allTime`、`finish.personalBest / newRecord`）；客户端对缺失的新字段容错。

### 小小🐰 助手入口（N4，接口见 API_SPEC 的 `POST /api/assistant`）

- 入口：右下角一个 80 px 的流光 AI 球（焦糖奶油色；出现时从一个点弹性长大到整个球，约 0.9 秒；滑回去时反过来缩回一个点并淡出，约 0.55 秒）（改自开源 VoiceOrbs「Iridescent Flow」，MIT，WebGL；只在屏幕上且页面可见时动，减少动态效果时一帧静止；不支持 WebGL 时换成纯 CSS 的玻璃球，D119），没有文字，读屏名「找小小🐰帮忙选面包」。只在首页「全部面包」区块进入视野后显示（区块顶部升到屏幕 70% 以上；首屏不显示），位置在纸袋栏上方（14 + 60 + 8 px + 安全区）；商品详情打开时隐藏；结算页显示在右下角，「确认提交预订」按钮在屏幕里时隐藏，不遮挡它。游戏页、订单页都没有。
- 提问（D120）：球时不时向左展开成深色胶囊，球缩到一半（38 px）放在左端，右边是一个问题（首页「这周四能取什么？」等，结算页「哪天还能取？」等，文案在 copy；1.5 秒后第一个，每个 5 秒、间隔 4 秒，一直都有）；这时点球就打开聊天并直接问这个问题；本次浏览打开过聊天后间隔变成 15 秒。
- 聊天卡片最上方正中是同一个球（108 px），下面是「小小🐰」；等回答时球进入「思考中」。输入框获得焦点（键盘弹出）时，卡片固定在可见区域底部（键盘上方）、高度等于可见区域，球缩成 44 px 放在标题左边。
- 面板：复用 Sheet（标题「小小🐰」、开场白、三个提示按钮、消息列表、输入框 + 发送、「请不要在这里输入微信号或地址」）。等待时显示输入中小点（减少动态效果时不闪动）。对话只在内存里（关闭面板保留，刷新即清空），每次最多发送最近 12 条，每条 ≤ 500 字。
- 建议卡片：商品名 × 数量、取货日期、备注 +「放进纸袋」。纸袋不空时先问「替换纸袋里的面包？」；确认后丢掉下架/不存在的商品、合并重复行、每行数量不超过每人上限，先 `setPreferredDate` 再替换购物车，首页上播放飞进纸袋，面板关闭。结算页打开时购物车变化会重新查日期并预选这一天。
- 错误：429（`ASSISTANT_LIMIT`）→「今天问太多啦，可以直接用下面的按钮下单」并禁用输入；503、403（`FORBIDDEN_ORIGIN`）、400、网络错误、12 秒无响应（客户端中止）→「小小🐰 暂时不在，可以直接下单哦」。下单流程不依赖助手。

### `/orders` 我的订单（D84）

- 首页右上角一直显示入口（小图标 +「订单」）。
- 这台手机浏览器里记下的订单：顾客每次成功打开 `/o/{token}`（包括刚下单）就记一条 `{token, orderNo, savedAt}`，按 token 去重，新的在前，最多 20 条，存 `localStorage["bb_orders_v1"]`，不上传。
- 列表每行：订单号、取货日期、当前状态、总额（每次打开页面用 `GET /api/o/{token}` 实时查，并发）；点一下进订单页。查到 404 的条目自动删掉；网络失败的行显示订单号和「重新加载」。
- 没有订单时：「还没有订单」。列表底部始终有「找不到订单？加店主微信要链接」（设置里有微信号且允许显示时带上微信号）。
- `noindex`、no-referrer，和订单页一样。

### 其他

- 404：「找不到这个订单，请检查链接是否完整，或加微信联系店主」。
- 页脚：店名、「联系店主：微信 {ownerWechatId}」（D11：是否在首页显示，由店主在设置里打开或关闭，默认关闭）。

## 店主后台（`/admin`，全部 noindex，需要登录）

### `/admin/login`

用户名、密码、「登录」。「忘记密码？」→「重置链接已发送到你的邮箱」。

### `/admin` 首页

- **接单开关**：大按钮「开启接单」/「暂停接单」，旁边写当前状态。暂停时弹出确认。
- 提醒条（有才显示）：「明天还有 3 笔订单没确认」，点击跳到筛选好的订单列表。
- **今天** / **明天** 两张卡片：每款商品个数、奶酪角要做几个大圆包、面团 1520 / 1600 g、布蕾杯数、配送 5 / 8、各状态订单数。
- **今晚要做的布蕾**：明天取货的杯数、批数。
- 快捷入口：订单、日历、代客下单、商品、设置。

### `/admin/orders` 订单列表

- 默认显示今天及以后的订单，按取货日期、订单号排序。
- 筛选：日期、状态（多选）、自提/配送、已付款/未付款、商品；搜索订单号或微信号。
- 快捷筛选：「未确认」「明天」「已完成未付款」。
- 每行：订单号、微信号、商品摘要（"红豆包×4、奶酪角×4"）、总额、自提/配送、取货日期、状态标签、付款标记。
- 每行可以直接点下一个状态（例如「标为已联系」），并复制微信号。

### `/admin/orders/{id}` 订单详情

- 全部信息、专属链接（「复制订单链接」，用于重新发给顾客）。
- 状态按钮：只显示可以去的下一个状态；「拒绝」「取消」要求填写原因。
- 付款：开关 + 付款方式。
- 「修改订单」：改商品数量、日期、自提或配送、微信号、备注。保存时如果超限，弹出所有超限项，以及「仍然保存（请写原因）」。
- 操作日志：时间、做了什么、原值 → 新值、原因。

### `/admin/orders/new` 代客下单

和顾客的结算页类似，但：日期可以选任何开放日期（不管截止）；超限时可以写原因强制保存；保存后直接是"已确认"，并显示专属链接方便发给顾客。

### `/admin/calendar` 开放日期

- 月历视图。点一个日期：勾选「这天开放」，填写这天的面团上限（空 = 默认 1600）、布蕾上限（空 = 默认 24）、是否配送、配送上限（空 = 默认 8）、备注。
- 每个开放日期上显示用量，例如「1460 / 1600 g · 布蕾 12 / 24 · 配送 5 / 8」；超限的日期标红。
- 取消勾选一个已有订单的日期时警告：「这天已有 6 笔订单，取消开放不会取消这些订单，只是不能再下新单」。

### `/admin/ledger` 记账（D87）

- 月视图：顶部月份切换（上个月 / 下个月）；本月营业额、总件数、运费合计、待收、按付款方式（微信 / Zelle / Venmo / 现金 / 其他 / 未注明）的金额；下面每天一行：日期、营业额、件数、待收（只列有数据的日子）。
- 点某天进日明细：每一单一行（订单号、顾客微信、商品 × 数量、金额、付款方式；未付款的标「待收」）；手动记录一行一条；底部当天汇总：每款件数和金额（各单实际行金额相加）、运费、营业额、待收。
- 「记一笔」：日期、金额、说明（必填，≤ 100 字）、付款方式、商品和数量（选填，可加多行）；可以改、可以删（确认）；都写操作日志。
- 计算口径：取货日在这一天、状态不是已取消/已拒绝的订单；已付款的计入营业额（含运费），未付款的计入「待收」；件数只算已付款订单和手动记录里填的商品。

### `/game/tu` 兔了个兔（D121–D126）

- 页面 `src/components/tu/**`；菜单、表单、退出询问、可关结果弹窗 + 底部条、👑、声音 / 震动都照搬 `/game`（文案复用 `copy.customer.game`，只有 `copy.customer.tu` 是新的）。排行榜复用 `LeaderboardView`（传入 `fetchTuLeaderboard`）。
- 玩的界面：左上分数、右上「第 N 炉」，顶栏右侧「退出」和声音；两张订单卡（面包图 + ×3 + 三个小圆点表示纸袋里已有几个）；中间是棋盘（DOM 按钮，不用 canvas、没有持续运行的 rAF，飞进纸袋用 Web Animations）；底部是 6 格牛皮纸纸袋（`public/brand/kraft.jpg`）。被压住的牌变暗且不可点；牌至少 44 px（320 px 宽时 7 列刚好），棋盘按当前一炉的外框缩放。
- 一次点击的事件（move、pack、order、batch、over）整体应用后再依次播放动画；换炉时短暂锁住点击（约 0.5 秒）。两次点击间隔小于 `MIN_TAP_GAP_MS` 的点击忽略。点击记录 `{ id, at }`，`at` = 开局以来的毫秒数；续玩时从上一次点击之后 120 ms 继续计时。
- 自动保存 `bb_tu_save_v1`：`{ v: 1, runId, seed, tiers, taps, nickname, expiresAt, score }`，继续 = 重放 `taps`。
- 接口 C6：`POST /api/game/tu/start`、`POST /api/game/tu/finish`（`{ runId, taps }`）、`GET /api/game/tu/leaderboard`，形状同 `/api/game/*`。

### `/admin/products` 商品

- 列表：照片、名称、价格、方式、状态，拖动排序。
- 编辑：名称、简介、照片（最多 6 张，一次可选多张上传；第一张是「封面」；拖动手柄或用「前移 / 后移」调顺序；删除先确认）、首页颜色（10 个命名色块 + 「自定义」颜色框 + 预览条，颜色上字看不清时提醒，D95）、单价、套餐大小、套餐价、名额方式及对应参数、提前天数（下面显示「需提前 N 天预订」预览）、一批几个（只用于汇总）、状态。
- 改了名额参数后：「以下开放日期会因此超限：10/30」。

### `/admin/game` 游戏（排行榜 / 面包）

「面包」页（手机优先）：最多 8 档面包 + 固定最后一档的大面包。每一档显示底色圆（带图片或名字首字）、名字、上移 / 下移、删除、换图片（去白底）、「改名字和底色」（商品等级可改底色，「用商品的颜色」恢复）。商品选择器旁边有「添加游戏面包」：名字（≤ 12 字）+ 底色选择器（预设 + 自定义 + 对比度提醒）→「添加」。没有商品的等级带「游戏专用」标签；还没有图片的游戏专用面包在游戏里画成底色圆 + 名字首字（D107）。

### `/admin/settings` 设置

截止时刻、默认上限、运费和免运费门槛、每单上限、店主微信号、是否在首页显示微信号、自提说明、两句"制作中"文案、修改密码。

### `/admin/logs` 操作日志

按时间倒序，可按订单号搜索。
