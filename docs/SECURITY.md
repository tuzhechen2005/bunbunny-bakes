# 安全与隐私

## 1. 存了什么个人信息

只有**微信号**和顾客自己写的备注。没有姓名、电话、邮箱、地址、付款信息。IP 只存加了密钥的哈希值，只用于频率限制，24 小时后删除。

## 2. 顾客订单链接

- `viewToken`：`crypto.randomBytes(32)` → base64url，43 个字符。不由订单号、微信号、时间推算。
- 订单页只显示这一笔订单；错误的 token 一律 404。
- 订单页、后台：`noindex`；`Referrer-Policy: no-referrer`，防止 token 通过来源网址泄露给外部网站。
- 不提供"用微信号查订单"。

## 3. 后台登录

- 只有一个管理员。初始用户名和密码来自环境变量，第一次运行种子脚本时创建；之后在后台修改密码。
- 密码：argon2id 哈希；至少 10 位。
- 连续 5 次失败锁 15 分钟，按用户名计数；失败和成功都写日志。失败提示统一为「用户名或密码错误」。
- Session：32 字节随机数放在 httpOnly、Secure、SameSite=Lax 的 cookie 里，数据库只存 sha256；30 天过期；改密码后所有 session 失效。
- 所有 `/admin/**` 页面和 `/api/admin/**` 接口在服务器端检查 session（middleware + 每个接口内部再查一次，不只依赖 middleware）。
- 非 GET 请求检查 `Origin` 头等于 `SITE_URL`。

## 4. 下单接口的防护

| 防护 | 规则 |
|---|---|
| 输入校验 | Zod：商品 id 必须存在；数量为 1–`maxQtyPerItem` 的整数；微信号 1–40 个字符；备注最多 300 字；日期格式正确 |
| 价格 | 前端传来的金额一律忽略，服务器重新计算 |
| 防重复提交 | 前端按钮锁定 + `idempotencyKey` 唯一 |
| 频率限制 | 同一 IP 10 分钟最多 5 笔（D86）；同一微信号同一取货日最多 2 笔未确认订单 |
| 陷阱字段 | 隐藏的 `website` 字段，有值就拒绝 |
| 验证码 | 第一版不用。出现垃圾订单后再加 Cloudflare Turnstile，并先在微信内置浏览器里测试 |

IP（`src/server/http.ts` 的 `clientIp`，下单、游戏、后台登录、小小🐰 共用）：优先用 Netlify 边缘按连接写入的 `x-nf-client-connection-ip`（顾客改不了）；没有时用 `x-forwarded-for` 的第一个（客户端可以伪造，只有本地 / 非 Netlify 环境才会走到这里），再没有用 `x-real-ip`，都没有就记为 "unknown"（D57），按 IP 的限制始终生效。

## 5. 定时任务接口

`Authorization: Bearer <CRON_SECRET>`，用常量时间比较。

## 6. 其他

- 全站 HTTPS（Netlify 自动）。
- 密钥只放在 Netlify 的环境变量里；`.env` 在 `.gitignore` 里。
- 错误信息不把数据库错误、堆栈返回给前端。
- 依赖保持最新；不引入用不上的第三方脚本（也就没有统计、广告脚本）。
- 备份：Neon 免费版自带短期的时间点恢复（保留多久以 Neon 当前的说明为准）；另外，后台提供「导出所有订单为 CSV」（P1），店主可以定期自己导出一份。


## 顾客找回订单（D84）

不提供“输入微信号查订单”：微信号在群里和加好友时都是公开的，只凭它就能看到别人的取货日期、商品和配送信息。顾客的订单只通过随机 viewToken 链接查看；「我的订单」只是把这台手机打开过的链接记在本机浏览器里。

## 消除大面包的防护（D102、D103）

| 防护 | 规则 |
|---|---|
| 分数 | 永远不信客户端：服务器用该局的 `seed` 和开始时的等级快照重放投放记录（`src/lib/game/replay.ts`），引擎在 600 次投放 / 200000 步时自己结束游戏，超出的记录直接拒绝，冷却 30 步，违规直接 `422` |
| 真实时间 | 模拟时长不能超过开始到提交的真实时间加 10 秒；投放记录和时长随结果保存，店主发奖前可人工查看 |
| 一次性 | 每个 `runId` 只能结束一次（原子更新 `finishedAt IS NULL`），开始后的下一个周一 0:00（America/Chicago）过期；种子来自 `crypto.randomBytes`，不可预测 |
| 输入 | Zod：微信号 1–40、昵称 1–10 个字符且不含控制字符、零宽和双向标记等不可见字符、换行；请求体有大小上限（4 KB / 64 KB）；JSON 内容类型必填 |
| 频率 | start、finish 各自同一 IP 每小时 60 次（IP 只存哈希，`GameRun.ipHash` 24 小时后清除；未结束且没有验分成绩的局过期后（下一个周一 0:00）由定时清理删除；已有验分成绩及操作证据与已完成局同样保留） |
| 隐私 | 榜单只返回昵称和打码微信号（前 2 + `***` + 后 2），完整微信号只在后台；`myBest` 只回给带着自己微信号来问的人 |
| 禁止 | `GameBan` 不区分大小写；被禁的微信号不能开始新局、不能结束进行中的局、不出现在榜上；店主可隐藏单条记录 |
| 错误 | 不返回堆栈或数据库错误；未知错误一律通用提示 |

## 兔了个兔的防护（D124，`/api/game/tu/**`）

和消除大面包相同（一次性种子、过期、输入、隐私、共用禁止名单），不同之处：

| 防护 | 规则 |
|---|---|
| 分数 | 服务器用 `replayTu`（`src/lib/tu/replay.ts`）和开始时的等级快照重放点击记录；被压住/不存在的牌、结束后还点、时间不递增、超过 20000 次 → `422` |
| 真实时间 | 相邻点击至少 120 ms；最后一次点击的时间不能超过开始到提交的真实时间加 10 秒 |
| 可疑标记 | 关卡是确定的，脚本可以在客户端算出解法再按"人的速度"提交，服务器无法完全挡住；所以点满 20000 次或点击间隔中位数 < 300 ms 的局存 `suspicious = true`，后台标出来，店主发奖前人工确认（D103），照常上榜 |
| 频率 | `tu_start_ip`、`tu_finish_ip` 各自每小时 60 次，和消除大面包分开计 |
| 请求体 | start 4 KB，finish 上限由 `MAX_TAPS × 30 bytes × 1.25 + 4 KiB` 推导（当前 754096 bytes；20000 条记录留 25% 余量和 4 KiB 外层字段空间） |

## 兔兔三连烤的防护（D135，S2，`/api/game/m3/**`）

沿用 TU 的昵称/微信校验、IP 哈希、共用封禁、周一过期、隐藏、幂等提交及脱敏排名；S2 不启用大厅入口或随机奖品抽取。

| 防护 | 规则 |
|---|---|
| 可比性与版本 | 至少六种面包才开局，截取前六种并存有序快照；finish 只用该快照。种子携带 `M3_ENGINE_VERSION`，无版本或版本不符的未完成局直接拒绝 |
| 分数 | 从头 `replayM3`，不信客户端分数；Zod 限制最多 `MAX_MOVES = 30`，坐标 0–7、时间为非负安全整数；非法交换、无消除、时间不递增、超限及多余 move/坐标字段均 `422`，不结束该局 |
| 真实时间 | 相邻步至少 `MIN_MOVE_GAP_MS = 150` ms；末步 `at` 不超过服务端经过时间 + 10000 ms |
| 可疑标记 | 间隔中位数 < `M3_SUSPICIOUS_MEDIAN_GAP_MS = 400` ms 标记 `suspicious`，仍上榜；不足两步为 false，完成 30 步不自动标记。仍需店主人工核查脚本成绩 |
| 频率 | `m3_start_ip` / `m3_finish_ip` 各每小时 60 次，独立于 BIG/TU |
| 请求体 | JSON；start 4096 bytes，finish `ceil(MAX_MOVES × 60 × 1.25) + 4096 = 6346 bytes`；沿用 TU 检查 Content-Length 和解析前文本长度，另有数组长度上限 |
| 证据 | `drops` 存完整 moves，`dropCount` 存步数，`playMs` 存末步毫秒；后台显示步数、秒数和可疑标记，修改奖励、隐藏和封禁都记 AuditLog |

## 小小🐰 下单助手（D117、D118，`POST /api/assistant`）

| 防护 | 规则 |
|---|---|
| 来源 | `Origin` 必须等于 `SITE_URL`，JSON 内容类型必填，请求体 ≤ 64 KB |
| 输入 | Zod：1–12 条消息，每条 ≤ 500 字符，最后一条是顾客；纸袋最多 50 行 |
| 次数 | 每个 IP 哈希每天 20 句、全站每天 500 句（America/Chicago），在调用 DeepSeek 之前原子计数（`AssistantUsage`）；访客自己超限不占全站额度（被全站上限拒绝的那句仍算访客的）；只存句数，今天以前的行定时删除。IP 见第 4 节（Netlify 上用 `x-nf-client-connection-ip`，顾客改不了） |
| 花费 | DeepSeek 预充值余额就是上限；`max_tokens 250`，最多 3 次模型调用（2 轮工具 + 1 次必须回答）；整个请求从到达起 8.5 秒预算（含数据库），每次调用 ≤ min(剩余, 4.5 秒)，剩余 < 1.5 秒不再调用，赶在 Netlify 10 秒上限之前回答；没配 key / 出错 / 余额不足 / 超时 → `503`（已有通过校验的建议卡片时返回卡片），下单不受影响 |
| 隐私 | 不存、不记录任何对话内容（日志只有 HTTP 状态码或 `timeout`）；发出前先把全角字母数字转成半角，再把像微信号、电话、邮箱、街道地址（中英文；中文地址只从「路/街…」或门牌数字开始遮，前面的面包和数量保留）的内容换成 `***`（`src/server/assistant/scrub.ts`，有单元测试）；系统提示里没有店主微信号 |
| 数据 | 模型只能调用 4 个只读工具（看菜单、查某天、找日期、配购物车）；工具背后是网站自己的名额代码，返回的只有商品名、价格、日期、状态和购物车件数，没有克数、上限、已用量、订单或顾客；没有读订单的工具 |
| 提示注入 | 工具参数用 Zod 校验；模型能产出的只有一段文字和一张建议卡片：文字去掉 HTML/Markdown/链接、最多 400 字；卡片的商品、数量、日期由服务器重新校验，`note` 同样清理。模型不能下单，顾客自己点「放进纸袋」再走正常下单流程（服务器照常重新校验和计算） |

### GRAB 重放与实时成绩（D145）

`/api/game/grab/*` 复用 M3 的身份验证、IP 哈希限流、禁止名单、周到期、脱敏及 no-store 策略。
服务端发带引擎版本的 128-bit 随机种子；finish/progress 均从开局 tiersSnapshot 和完整 launches
重放，绝不采纳客户端分数或当前后台配置。GrabReplayError 映射为 VALIDATION。

入口在解析 JSON 前限制 41596 字节，zod 限制 6000 条、0–6000 整数 tick；引擎拒绝不递增日志、
超过 120 次忙碌输入、结束后点击、观察点之后的点击。客户端只记录接受的点击，忙碌时点击无效。
毫秒时间从 tick 单向推导并验证往返一致，不存在独立可伪造的 `at` 时间轴。
endTick 推导的有效时长必须 ≤ 开局至请求的实际时间 + slack，且 ≤ 60 秒 + 本局已送达闹钟奖励 + slack。
隐藏和暂停可以令墙钟时间比有效时间更长；结束时仍在收回的物品不算分。

进度请求先预留共享 8 秒节流再重放；日志必须延续已验分前缀，游玩时间不能倒退。
已完成的局不再被进度覆盖；首次验分和分数增加才推进同分排序时间。中位间隔 <350ms 标可疑但保留排名。
发奖游戏首次上线的下一周才能进入候选池，配置不足三档时不可新选；实际日期部署前核对。
