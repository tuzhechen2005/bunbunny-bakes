# 前端改版 SPEC v2（2026-10-23 定稿）

> 来源：店主在手机上试过可上手原型 v2 后定稿（决策 D74–D82，取代 v1 的 D65、D67、D68 和 D71 的空袋文案）。与其他文档冲突时以 `DECISIONS.md` 为准。
> 业务规则、金额计算、接口、数据全部不变；只改“看起来和用起来的感觉”。
> 原型是唯一的视觉参考：颜色、尺寸、缓动、时长都以原型为准（开发者拿到的是原型源码，路径写在任务说明里）。

## 1. 目标与非目标

**目标**：高级、简洁、有下单欲望；三个招牌时刻：绳子上的面包（拖、晃、自转后取下）、纸袋里真的会堆起来的面包、下单时砸下来的印章。
**优先级**：下单顺畅 > 速度 > 惊艳。任何动效都不能挡住或拖慢下单。
**文字越少越好**（D75）：每屏只留名字、价格、按钮和必须的提示。

**非目标**：后台改版（后台保持现状）；WebGL、持续运行的 Canvas、声音；新增业务功能；改动 `src/domain/**`、`src/server/**` 的行为；电脑版单独排版（电脑上就是居中的手机宽度一栏，两边铺当前面包的底色）。

## 4. 页面

### 4.1 首页
1. **顶部**：logo +「的大面包」。
2. **标语**：一行「今日出炉，限量手作。」+ 小字。
3. **绳子**：拧股麻绳（底色 + 斜纹 + 高光 + 投影）横穿屏幕，方形照片用木头晾衣夹夹着；中间那张正对，两边露边并缩小 14%；照片以夹子为支点钟摆晃动，由绳子加速度驱动；进页面时照片依次从上方落到绳上。
   - 拖动区域是整块彩色区域（按钮除外）。**触摸用 touch 事件**：第一下移动就判断方向（横向偏置 |dx| ≥ 0.75|dy|），横向时 `preventDefault` 阻止页面和外层 App 抢手势；竖向交给页面滚动。鼠标用 pointer 事件。一次甩动最多 ±1 张。
   - 点中间那张：照片绕竖轴自转一圈（约 0.64 s，背面是同一张照片稍暗），转到约 0.54 s 时放大成详情（FLIP）。点两边的先滑到中间。
   - 「点击试试！」在中间照片右上角、绳子上方，第一次打开详情后淡出。
4. **当前面包**：名字（换款时左右滑入）、单价（数字滚动）、「4 个 $x」、圆形「+」（直接放进纸袋，从照片飞出）。下面四个小横条表示第几款。
5. **全部面包**：两列照片格，「+」在照片右下角，有数量后变成「− n +」。这是保底下单路径（读屏、键盘、减少动态效果）。
6. **页脚**：大 logo +「的大面包」+「微信 xxx」（按设置显示）。
7. **底栏**：左边小纸袋（窗里能看到堆着的面包，右上角红色件数），右边黑色长按钮「你的纸袋 + 金额 + 白色圆形箭头」。点击时箭头先加速冲出右边再从左边滑回（约 0.3 s）再打开纸袋。

### 4.2 详情（取下来）
- 背景是当前面包颜色；顶部：向下箭头（挂回去）、上一款 / 序号 / 下一款；照片带着夹子；名字、简介、单价和 4 个价、布蕾提示、数量；底部吸底按钮「放进纸袋 · 小计」，左边让出底栏小纸袋的位置（底栏此时只留纸袋）。
- 在照片或顶部往下拉超过 90 px（或点向下箭头）：照片飞回绳子，绳子和照片晃一下。

### 4.3 放进纸袋
- 圆形小图沿弧线飞向纸袋窗口（约 0.62 s，先抬起、转一点、再落下缩小），落进窗里变成一个物理圆片：重力、互相碰撞、贴墙、滚动，全部静止后停止计算；件数多时圆片变小，最多显示 24 个。
- 纸袋落袋时压扁一下并以底部为支点摆动；安卓 `navigator.vibrate(12)`。可以连续添加，动画从不挡点击。

### 4.4 纸袋页
- 底部弹出白色面板，大纸袋一半露在面板上方；按住纸袋可以拖着晃，里面的面包跟着加速度滚动。
- 每行：照片、名字、行价、「− n +」；减到 0 的那份面包从袋口飞出。小计（大号数字）+「去结算 →」（同样的箭头动效）。

### 4.5 结算页
- 白底；标题「确认预订」；分 1–4 四段：取货日期（横向日期卡，选中变黑）、自提 / 配送（滑块）、微信号（下划线大输入框）、备注；运费（只在配送时显示）、总额（大号数字）；「收到货再付款」；黑色「确认提交预订」。
- 流程、字段、校验、错误处理、接口全部不变；错误出现在对应段落下并轻轻抖一下。

### 4.6 订单页
- 刚下单（`?new=1`，只播一次）：装着这单面包的纸袋从下方弹入 → 袋口折下 → 木柄印章从上方加速砸下：纸袋压扁、整屏震、红色冲击波、墨点飞溅、袋里面包跳一下、安卓震动 → 印章抬起离开，留下实心红底反白字的「已预订 + 订单号」圆章（外圈 `stampRing`）→ 标题、明细依次出现。总长约 2 s。
- 之后（以及再次打开时直接显示）：纸袋（已盖章）、标题、订单卡片（订单号、取货、明细、运费、总额、备注）、保存链接卡片、店主微信、取消订单。

### 4.7 空状态与其他
- 加载失败、空菜单、404：logo + 一句现有文案，安静克制。暂停供应的商品照片变灰，写「暂停供应」，不能放进纸袋。

## 5. 动效与无障碍

- 物理：`src/lib/motion` 的弹簧（绳子 1.7 Hz / ζ0.9）、钟摆（L 0.42 m、0.85 临界、驱动上限 5）、手势参数（橡皮筋 0.45、速度窗口 100 ms、停顿 80 ms）；纸袋堆叠用新的 `pile` 模块（纯 TS + 单元测试，固定 1/120 s 步长）。全部静止后停止 rAF。
- **减少动态效果**：不晃、不飞、不转、不震屏，只淡入淡出；纸袋里的面包直接落定；印章直接显示在纸袋上。
- **掉帧降级**：持续低于约 45 fps 时关掉钟摆和印章的溅墨。
- 读屏和键盘：绳子是 listbox（左右键、回车）；列表是保底路径；所有按钮 ≥ 44 px、焦点可见；每次放进纸袋有 `aria-live` 播报。

## 6. 性能与兼容（验收标准）

1. 中端安卓 + 4G + 微信内置浏览器：首页 2.5 秒内可以点「+」。
2. 首页首屏改版新增 JS + CSS ≤ 60 KB（压缩后，对比 main），字体子集合计 ≤ 125 KB（D73；现在约 73 KB）；品牌素材合计约 100 KB；照片懒加载（绳子中间那张除外）。
3. 动画在中端机上约 60 帧。
4. 微信内置浏览器（iOS、安卓）、Safari、Chrome 手机版都能正常下单。
5. 现有全部单元、数据库、e2e 测试保持通过；e2e 选择器跟着新结构更新，覆盖的流程不减少。
6. 所有可见文字来自 `src/copy.ts`；顾客端不出现内部数据。
